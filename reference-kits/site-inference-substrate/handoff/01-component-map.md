## Notes that change a build decision

- **K3s vs RKE2 follows the site class, not preference.** The grounding
  architecture's four site classes map single-node K3s (storage cabinets,
  small solar) up to 3-node RKE2 CIS-profile with FIPS (the strictest
  class). The three-node threshold is driven by stacking requirements —
  Longhorn replica HA, NeuVector's three-Controller consensus, RKE2's
  embedded-etcd quorum — a site that needs any of them properly needs all
  three nodes. Datastore is baked in at image-build time.
- **AI footprint.** No LLM tier exists in this use case, so SUSE AI floors
  do not apply. GPU model and count per site are discovery-phase outputs of
  the selected model classes' measured throughput; CPU-only inference is a
  legitimate outcome for low-rate advisory models. The demo scorer is
  CPU-only by design and is not a performance analog.
- **Governance.** Advisory outputs only — nothing this substrate emits is
  presented to plant operators as a control signal, and nothing in the
  design has a write path toward OT. The evidence stream is generated by
  the platform; assembling it into an audit narrative is the services
  engagement's work.
- **Security.** NeuVector runs complete on every cluster with policy as
  CRDs in Git; host integrity comes from the sealed EIB image plus TPM2 +
  Keylime attestation — the attestation pull is the single inbound flow the
  production design admits, and the strictest site class may restrict it to
  onboarding-time only. Full enforcement requires real k3s, not the
  nested-Docker lab cluster.
- **Simplifications in this demo, stated plainly:** the four enclave
  containers share one pod and its volumes (production separates concerns
  on the same single-node cluster); the evidence signature is an HMAC with
  a shared demo key (production: per-site PKI keys, independently
  verifiable); the WORM property is file-permission + chain verification
  on a local directory (production: object-lock bucket with write-only
  per-site credentials); the central side is one stub container standing in
  for the ML platform and the evidence store; telemetry is synthetic and
  the serving models are illustrative stand-ins behind the real protocol
  surface. None of these change the pipeline semantics the demo proves.
